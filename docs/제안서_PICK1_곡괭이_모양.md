# 제안서 PICK-1 — 곡괭이 모양: 보령 탄광 곡괭이를 Blender · Meshy 두 개로 만들어 비교

옆 가지 `pick-hands`(작업 폴더 `Tunnel/unity-pick`), 2026-09-27. **승인(09-27) → 판정 ① B(Meshy) → 차례 4 → 판정 ② 통과(09-27). 휘두르기는 MINE-1 로.**

**왜** — 사용자(09-27, ART-1 차례 2 도중): "곡괭이의 생김새와 곡괭이질 소리가 현실적이었으면" + "워독스의 재질과 느낌". 사용자 순서 "캐기 한 벌"의 한 조각이다. 뒤에 MINE-1(콱콱 캐는 연출)이 이 곡괭이와 3D-P 손을 쓴다.

**하나씩 낸다**(사용자 규칙). 이번 PICK-1 = 곡괭이 모양 하나. 번호만: **3D-P** 1인칭 손·팔 — 곡괭이 자루 굵기·길이가 정해져야 손이 쥐는 자리를 맞출 수 있어서 곡괭이가 먼저다. 사용자 답(09-27) "근로장갑 + 검은 긴소매, **멀티가 될 때 다른 플레이어의 모습도 이와 똑같이**"는 3D-P 제안서에서 다룬다.

**지어낸 것**(출처 없음 — 표시해 둔다): 쐐기 모양 · 날 끝이 밝게 닳은 정도 · 나무 갈라짐 수. 한국 기록에 무게·나무 종류 없음.

**지금 게임과 같게 두는 것**: 축(자루 +Y, 머리 너비 X, 머리가 위) · 원점 = 자루 끝에서 15 cm(쥐는 곳) · 물체 이름 `PICK_Head` · `PICK_Handle`(던진 곡괭이가 머리를 찾는다). 그래서 `PICK_POS` · 기울기 · 휘두르기 값은 안 바꾼다. 화면에서의 크기는 지금(88 cm × 0.75배 = 자루 66 cm)과 거의 같다 — 새 것은 실물 크기 × 1.0 배.

## 두 가지로 만든다

**A. Blender 코드** — `blender/props/make_pick.py`(새 파일). 위 표의 숫자로 그물을 만든다(자루 = 굵기가 줄어드는 통 + 끝 부풂 + 얕은 갈라짐, 머리 = 둥근 쇠 통 + 네모 꼭지 + 휜 날 + 쐐기). 질감은 Poly Haven CC0(녹슨 쇠 · 낡은 나무 — ART-1 처럼 이름·출처를 README 에) + 탄가루 어둡게. 결과 `Assets/Tunnel/Props/pick_blender.glb`. **비용 0.**

**B. Meshy.ai** — 모양은 A 와 같게 하고 살(재질·잔모양)만 Meshy 가 입힌다(규칙: 모양 먼저, 생성기는 나중). 입력 = **A 를 흰 바탕에서 찍은 그림 4장**(옆 · 앞 · 위 · 비스듬히) + 짧은 글("old coal miner's pick, blackened iron, cracked dark wood"). 보령 박물관 사진은 넣지 않는다(사진 이용 조건을 확인 못 함). `gen_meshy.py <이름> <그림들> --out props` → `fit_prop.py` 표에 한 줄 더해 크기·축·원점·머리/자루 가르기 → `Assets/Tunnel/Props/pick_meshy.glb`. **크레딧**: 뽑기 전에 잔액과 값을 보여 드린다. 한 번 뽑고 멈춰 보여 드린다(첫 결과가 틀리면 더 안 뽑는다).

## 만드는 차례 (판정 두 번)

1. **A 만들기** → 자기 검사 · 사보타주 FAIL 확인.
2. **B 뽑기** (A 그림 4장 입력) → 맞춤.
3. **비교 한 장**(판정 ①): 같은 빛·각도로 A · B · 보령 사진을 나란히 — 옆모습 · 비스듬히 · **1인칭 카메라 자리**(시야 80°, 지금 `PICK_POS`)에서 갱도 바위 배경으로. 사용자가 하나 고른다(둘 다 아니면 무엇이 틀렸는지 듣고 고친다).
4. 고른 것을 게임에 넣기: `Tuning.PICK_MODEL` 한 줄 · `PICK_LENGTH_M` 0.88 → 0.68 · `PICK_SCALE` 0.75 → 1.0 → 곡괭이 구간 빠른 검사(`tools/quick.sh`) → 전체 `build.sh` → 커밋 → **실행 파일 판정 ②**.

## 검사

- **Blender 자기 검사**(`make_pick.py`, FAIL 이면 멈춤): 긴 축 68 cm ±1 % · 머리 끝에서 끝 32 cm ±1 cm · 날이 한쪽에만(반대쪽 꼭지 ≤ 머리의 20 %) · 자루가 머리 쪽이 더 굵음 · 이름 `PICK_Head` · `PICK_Handle` · 면 ≤ 8,000 · 그림이 GLB 안에. **사보타주**: `SABOTAGE=twopoint`(양쪽 날) · `noscale`(크기 안 맞춤) · `thinhead`(자루가 끝 쪽이 더 굵음) → 각각 FAIL 을 보고 나서 믿는다.
- **Meshy 판**: `fit_prop.py` 의 검사 그대로(길이 ±1 % · 면 수 · 원점 · 머리 폭 — 머리 폭 기준 0.3 m 는 새 머리 32 cm 에 겨우 맞아 **0.25 m 로 낮춘다**).
- **게임(배포물)**: 새 검사는 안 만들고 이미 있는 곡괭이 검사를 새 모델로 돌린다 — `props_real_size`(0.68 m) · `viewmodel_overlay` · `pick_not_burnt` · `pick_head_glows_within_reach`(머리를 찾나) · `thrown_pick_rests_on_floor`(작아진 머리로 바닥에 눕나) · `pick_breaks_at_zero`. 새 게임 검사가 필요하면 `M1Check` 를 고쳐야 해서 main 에 합칠 때 한다.
