# 제안서 3D-③b M2 — 달리기 손 짚기 (`run_knuckle`)

작성 2026-09-19 (36차). 위 문서: `docs/제안서_3D3b_괴물_동작_다시_짜기.md` Step 6 의 M2. **승인 전에는 이 문서와 HANDOFF 말고는 아무것도 안 고쳤다.** 아래 숫자는 모두 읽기만 하는 측정과, 저장소 밖 임시 폴더에서 돌린 시험에서 나왔다.

## 한 줄 요약

지금 달리기(`run`, Mixamo running crawl)는 **손가락만이 아니라 손목째 바닥 밑에 있고, 어깨가 엉덩이보다 낮다.** 고쳐 쓰기보다, M1 에서 만든 걷기 생성 스크립트에 **숫자만 바꿔 넣어 달리기를 새로 굽는 쪽**이 싸고 확실하다 — 시험에서 이미 됐다. (위 문서의 "가. Mixamo 고쳐 쓰기"를 "나. 스크립트 키"로 바꾸는 **결정 변경 제안**이다.)

## 1. 지금 `run` 을 재 보니 (09-19, Blender 읽기만, 모델 크기 1 · 게임은 ×1.5)

| 잰 것 | 값 | 뜻 |
|---|---|---|
| 한 주기 | 19 프레임 = 0.63 s | |
| 발톱 끝 가장 낮은 곳 | **−0.32 m** (게임 −0.48 m) | 바닥 밑 |
| **손목** 가장 낮은 곳 | **−0.13 m** | 손가락만 굽혀서는 못 고친다 — 팔 전체가 바닥 밑 |
| 발톱 끝이 바닥 위에 있는 프레임 | 20 중 2 | 거의 내내 뚫는다 |
| 어깨 높이 0.54~0.63 / 엉덩이 0.64~0.72 | **어깨 < 엉덩이** | 원리 P1(어깨가 엉덩이보다 높다)과 반대 |
| 머리 높이 | 0.57~0.65 (게임 0.86~0.97 m) | 쫓아오는 괴물 머리가 내 허리 높이 |

게임에서는 `StalkerAnim.LateUpdate` 의 "팔 들기"가 매 프레임 어깨를 3° 씩 들어 올려 이걸 가린다. 그래서 달릴 때 팔이 어색하게 튄다(3D-③ 판정 목록에 있던 걱정).

**왜 고쳐 쓰기가 안 싼가**: 손목이 13 cm 밑이라 어깨를 25 cm 넘게 올려야 한다 → 척추 각도를 다 바꿔야 하고 → 머리·팔 궤적도 다 바뀐다. 남는 것은 다리 박자뿐이다. 그러면 Mixamo 클립을 "고친" 것이 아니라 거의 새로 만든 것인데, 스크립트는 더 복잡해진다.

## 2. 시험 — 걷기 스크립트에 숫자 8줄만 바꿔 달리기를 뽑아 봤다

`blender/anim/walk_knuckle.py` 를 임시 폴더에 복사해 값만 바꿈(저장소·GLB·Documents 안 건드림, 내보내기 없는 `QUICK=1 SHOTS=1`):

| 값 | 걷기 | 달리기 시험 |
|---|---|---|
| 한 주기 | 1.0 s (30 프레임) | **0.67 s** (20 프레임) |
| 원래 빠르기 | 2.5 ÷ 1.5 = 1.67 m/s | **6.5 ÷ 1.5 = 4.33 m/s** (추격 빠르기에 맞춤) |
| 짚는 몫 (손 · 발) | 0.45 · 0.55 | **0.25 · 0.30** → 네 발이 다 뜨는 순간이 생긴다 = 뛴다 |
| 짚는 순서 | 왼손 → 오른발 → 오른손 → 왼발 (0.25 씩) | **왼손 0 → 오른손 0.12 → 오른발 0.5 → 왼발 0.62** (손 둘이 먼저, 발 둘이 뒤 — 고릴라·개 뜀박질) |
| 몸 오르내림 · 드는 높이 | 2.5 cm · 손 20 발 14 cm | 5 cm · 손 30 발 22 cm |

결과 (스크립트 자기 검사 20개 중 18 PASS):
- 발톱 끝 가장 낮은 곳 **+0.030 m**(지금 −0.32) · 손 살 가장 낮은 곳 +0.024 m → Unity 팔 들기가 걸릴 일이 없다
- 짚은 손발 미끄러짐 0.000~0.001 m/s · 짚는 동안 뒤로 4.33 m/s(= 원래 빠르기)
- 어깨 1.14 > 엉덩이 0.87 (게임 1.71 / 1.30 m) · 무릎 안 닿음(게임 0.36 m) · 머리 고정 · 손가락 굽음 0.800
- FAIL 2개는 검사 쪽 문제: "짚은 프레임 ≥ 4"인데 손 짚는 몫 0.25 × 20 프레임에서 가장자리를 빼면 3 프레임. 빠르기 값 자체는 맞다 → M2 에서 이 검사를 "≥ 3"으로 (달리기만).
- 그림: `build/check_3d3b/42_run_test_{side,front}_sheet.png`(0.067 s 간격 10장, Blender 시험 그림 — 게임 화면 아님). 손 둘이 앞을 찍고 → 몸이 넘어가고 → 발 둘이 밀고 → 공중, 순서가 읽힌다.

**시험에서 모자란 것 (M2 에서 채울 것)**: 몸통이 막대처럼 곧다. 뜀박질은 허리가 접혔다 펴져야 한다(손 짚을 때 등이 말리고, 발로 밀 때 펴짐). 지금 스크립트는 몸 오르내림이 한 주기에 두 번인데 뜀박질은 한 번이다.

## 3. 하는 일

1. `walk_knuckle.py` 의 걸음 값을 **걸음표(딕셔너리) 둘**로 묶는다: `walk_knuckle`(지금 값 그대로) · `run_knuckle`(위 표). 파일을 새로 만들지 않는다 — 같은 스크립트가 두 클립을 차례로 굽는다. 걷기 클립은 값이 같으니 결과도 같아야 한다(검사: 걷기 자기 검사 숫자가 지금 로그와 같다).
2. 달리기에만 더하는 것 두 가지: **허리 접기**(엉덩이·척추 숙임을 주기에 한 번 흔듦, 제안값 ±8°) · **몸 오르내림 한 주기 한 번**.
3. GLB 다시 굽기 — 클립 15 → **16** (`run_knuckle` 추가). 옛 `run` 은 남긴다(사보타주·비교용, M1 의 `walk_crouch` 와 같은 대접).
4. Unity: 조사·추격·철수 칸을 `run` → `run_knuckle` 로. 재생 배수 = 빠르기 ÷ (4.33 × 1.5): **추격 ×1.00 · 조사 ×0.77 · 철수 ×0.62**.
5. 턱(달릴 때 20°)·머리 돌리기·목은 동작 이름으로 걸려 있는 곳만 `run_knuckle` 을 더한다.

## 4. 검사

**Blender 자기 검사** (달리기 클립에도 걷기와 같은 검사): 첫 = 끝 자세 · 짚는 동안 4.33 ± 0.08 m/s · 미끄러짐 < 0.05 · 발톱 ≥ 0.025 m · 손 살 ≥ −0.01 · 어깨 > 엉덩이 · 무릎 안 닿음 · **새로: 네 발이 다 뜬 프레임 ≥ 2**(걷기가 아니라 뛰기). 사보타주 `SABOTAGE=noplant` 가 달리기에서도 FAIL.

**봇 검사** `bash tools/build.sh -only anim` (배포 실행 파일):
1. `anim_run_knuckle_plays` — 추격 중 틀어진 클립 = `run_knuckle`, 배수 0.95~1.05 (조사 0.72~0.82)
2. `anim_run_knuckle_plants` — 추격 5 s 동안 **팔 들기 0번** · 두 손 각각 바닥 0.05 m 안에 있는 몫 ≥ 15 % 제안값(걷기는 25 %, 달리기는 짚는 몫이 짧다)
3. `anim_feet_do_not_slide` — 있는 검사, 달리기 미끄러짐 ≤ 0.4 m/s (지금 0.31)
4. 추격 중 한 주기 평균 어깨 > 엉덩이
5. 있는 검사 전부(107개) + fps ≥ 60

사보타주 **`oldrun`**(추격을 옛 `run` 으로) → 1·2·4 FAIL 을 먼저 본다.

**캡처** `build/check_3d3b/42_run_{old,new}_{7m,2m}_sheet.png` — 같은 자리에서 옛 달리기 / 새 달리기, 0.067 s 간격 한 주기.

## 5. 봇으로 답이 안 나오는 것 — 판정 목록 (F1 → `9` → `N` 으로 `run_knuckle`, 그리고 `0` 으로 실제 추격)

- [ ] 7 m: 쫓아올 때 "네 발로 뛰어온다"로 읽힌다 — 옛 달리기와 비교
- [ ] 2 m: 손이 바닥을 찍고 몸이 그 위로 넘어온다(팔이 몸보다 먼저, P7)
- [ ] 허리가 접혔다 펴지는 것이 보인다 / 막대 같다
- [ ] 조사(5.0 m/s, ×0.77)가 느린 화면처럼 보이지 않는다 — 보이면 조사용 값을 따로 굽는다
- [ ] 철수(4.0, ×0.62)도 같은 질문
- [ ] 무섭다 / 안 무섭다를 "7 m 윤곽 / 2 m 그늘 / 움직임"으로

## 6. 안 하는 것

- 옛 `run`·팔 들기 안전망 지우기 — `crawl`(벽타기)이 아직 팔 들기를 쓴다. 위 문서대로 M4 뒤.
- 목 행동 연결(수색 때 목 내밀기·잡기 때 찌르기) — 달리기와 다른 일이라 다음 제안서로 따로.
- 소리(네 발 짚는 박자) — S2 보류 그대로. 박자 값(0 · 0.12 · 0.5 · 0.62)만 HANDOFF 사운드 요청에 적는다.
