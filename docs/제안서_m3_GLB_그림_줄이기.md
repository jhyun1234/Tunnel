# 제안서 m3-④ — GLB 162 MB 줄이기 (그림 4K → 2K)

작성 2026-09-22 (`m2-body` 가지). HANDOFF 0절 "다음 일 ④". 손목 판정 뒤 승인받아 구현한다.

## 한 줄
굽기 마지막에 **GLB 안 그림 중 4096² 를 2048² 로 줄이는 한 단계**를 `tools/bake_m3.sh` 끝에 붙인다. Blender 파이프라인·재질·UV 는 안 건드린다.

## 지금 확인한 것 (09-22, `miner_m3.glb` 162.6 MB)
- 그림 31장 147.2 MB · 그물·뼈·클립 15.4 MB. 그림이 90 %다.
- **4K 가 7장 = 117 MB**: 노멀 PNG 4장(몸 19.3 · 머리 18.5 · 속 목 21.6 · 손 20.6) + 제 색 JPEG 3장(몸 12.9 · 머리 9.4 · 속 목 14.6). 나머지 24장(2K 이하)은 합쳐 30 MB.
- Meshy 가 뽑은 부위 넷(몸·머리·속 목·손)이 저마다 4K 한 벌씩이다. 갱목·못·끈(Poly Haven)은 512~1024.
- 배포물 `sharedassets0.assets.resS` 781 MB — glTFast 가 GLB 속 그림을 **압축 없이**(4K RGBA + 밉맵 ≈ 89 MB/장) 넣는다. 7장 × 89 ≈ 620 MB 가 이것.
- 화면 밀도: 괴물 키 2.3 m 가 2 m 앞에서 화면 약 1000 px. 몸 UV 한 벌이 2K 여도 픽셀당 텍셀 2 개쯤 — 4K 는 남는다.

## 하는 일
1. `tools/shrink_glb.py`(새로, Python + Pillow): GLB 를 읽어 `images` 중 한 변이 2048 을 넘는 것만 LANCZOS 로 2048 로 줄여 버퍼를 다시 짠다. PNG 는 PNG 로, JPEG 은 JPEG 품질 92 로. 노멀맵은 줄인 뒤 다시 정규화하지 않는다(2 배 축소 평균은 길이 오차 1 % 미만, Unity 가 샘플 때 정규화).
2. `tools/bake_m3.sh` 끝, `walk_knuckle.py` 뒤에 `python tools/shrink_glb.py Assets/Tunnel/Monster/miner_m3.glb` 한 줄.
3. 검사(스크립트 안, 굽기 때 PASS/FAIL 출력): ① 그림 한 변 ≤ 2048 전부 ② GLB ≤ 85 MB(실측에 맞춰 70 → 85) ③ 그림 장수·재질의 그림 참조 인덱스 변함 없음. 사보타주 `SABOTAGE=skip`(줄이지 않고 통과시킴) → ①② FAIL 확인.
4. 배포물: `MakeScene` → `-only monster` · `-only lure` · `-only anim` 셋 다(그림만 바뀌지만 규칙대로). 살 모습 검사 문턱은 그대로 — 탄 픽셀 2.59 % · 얼룩 0.869(≥ 0.85, 여유 작음) 가 어떻게 움직이는지 숫자로 적는다.

## 안 하는 것
- Meshy 원본·Blender blend 의 그림은 안 줄인다(원본 4K 는 남겨 둔다 — 나중에 근접 컷이 필요하면 되돌릴 수 있게).
- 2K 그림(몸 디테일 노멀 7.4 MB 등)은 안 건드린다. 필요하면 다음에.
- Unity 쪽 텍스처 압축(glTFast 임포터 설정)은 이 제안 밖 — 배포물 크기를 더 줄이려면 별도.
